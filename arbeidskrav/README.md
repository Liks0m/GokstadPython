## Task 2 – Data structures and data processing

**File:** `oppgave-2.py`

**Summary:** Task 2 is about analyzing, storing and logging study sessions. It uses the same while Loop logic as task 1

**Data structure:** A list of `dict`s with the fields `topic`, `duration_minutes` and `status`. Dicts are good to use for storing data that is structured and can store values by fields where each field is a key and the values are underlying items. Tuples can be used to store multiple different types but tuples are immutable and are often hard to access and change. Lists are mutable and are easy to iterate over and are generally easy to work with and makes accessing and managing the underlying data easy you can append items (in our case dicts) without having to make a brand new tuple which you need to do with tuples since you do not have an append function for tuples as you do with lists.

**Example sessions:** The random study sessions are generated randomly by using the function random which chooses from a list of topics which range from Python to History. The different fields is put into a class called ExampleStudySession. I choose to use class as it has good reusability. I did not have to make 5 functions that all do the same thing. In my python programming sessions I have found that making functions and features that have no reusability is bad code design so I aim for good reusability. With a class I can just state what "field" I want and the underlying key values will be mapped. I choose to make a for loop in the range of 5 which makes a dict out of the dict structure I already have at line 5 which looks something like this: study_session = {"topic": "", "duration_minutes": 0, "status": ""} so the topic key would be mapped to the class field of x.topic et cetera.

**Known limitations:**

- `field_error()` only sets `id` when the id is an int. If the id in a row is not a number (for example `abc`), `id` still holds the value from the row before (or is not defined at all if it is the first row), so the message shows the wrong id or the program crashes.
- `field_error()` does not warn about negative `minutes` (for example `-5`). The row is still removed by `is_valid_request()`, but the user gets no message explaining why.
- The four categories are written directly into `file_writer()`. If a new category shows up in the CSV it is counted, but it is not shown in the report.
- If every row were invalid, `time_list()` would be empty and the average calculation would crash with `ZeroDivisionError`.
- The file paths are relative, so the program has to be started from inside `arbeidskrav/`.
